## 1. 已完成功能中的已知缺陷

### 1.1 HITL 审批：AsyncSqliteSaver 同步接口失效

**严重程度**：🔴 高

**问题描述**：生产环境的 Checkpointer 使用 `AsyncSqliteSaver`，其同步 `get_state()` 方法不可用（挂起或抛错），但异常被 `except Exception` 静默吞掉。这导致 `_get_all_interrupt_tools` 静默返回空列表，fallback 只生成 1 个 decision，而 SDK 的 `HumanInTheLoopMiddleware` 要求 decisions 数量等于 `action_requests` 数量，从而报错 "Number of human decisions (1) does not match number of hanging tool calls (2)"。

**影响**：多工具同时触发审批时，审批全部失败并进入死循环。

**整改建议**：
- 所有读取 interrupt 状态的辅助函数改为 `async`，使用 `agent_graph.aget_state()` 而非 `get_state()`
- 兼容 value 为 pydantic `HITLRequest` 对象（`model_dump()` 归一化为 dict）
- 单元测试的 graph mock 必须使用 `AsyncMock` 设置 `aget_state`
- 移除所有对 `get_state()` 的同步调用

### 1.2 SubAgent 委派列表白名单 Bug

**严重程度**：🔴 高

**问题描述**：`_subagent_summaries` 函数在构建子代理列表时未正确传递 `subagent_ids` 参数，导致委派列表显示不准确。LLM 看到的子 Agent 描述与实际可委派的 Agent 不一致。

**影响**：主 Agent 可能委派给不可用的子 Agent，或遗漏可用的子 Agent。

**整改建议**：
- 确保 `SubAgentRegistry` 在构建委派列表时完整传递所有子 Agent 的 ID 和描述
- 添加端到端测试验证委派列表的完整性

### 1.3 审批按钮点击无响应

**严重程度**：🔴 高

**问题描述**：新会话中 `currentSessionId` 为 `null`，导致 `submitApproval` 静默退出，审批按钮点击无任何反馈。

**影响**：用户无法完成 HITL 审批流程。

**整改建议**：
- 审批请求发送前校验 `session_id` 是否存在
- 缺失时给出明确错误提示，而非静默失败
- 前端在收到 interrupt 事件时确保 `session_id` 已正确设置

### 1.4 SDK 模型对象 repr 泄漏到 UI

**严重程度**：🟠 中

**问题描述**：OpenSandbox SDK 返回的 pydantic 模型对象（如 `SandboxStatus`）直接 `str()` 后会把整个 repr 渲染到前端，如 `state='Running' reason=... message=... last_transition_at=datetime(...)` 撑破表格列。

**影响**：沙箱控制平面页面文字堆叠、布局错乱。

**整改建议**：
- 归一化函数按语义优先级取字段：`getattr(raw, 'state')` → `getattr(raw, 'value')` → `str(raw)`
- 不同模型用各自的归一化函数（platform 单独处理 os/arch）
- 添加 UI 层面的文本截断保护

### 1.5 沙箱同步 manifest 未绑定 container_id

**严重程度**：🟠 中

**问题描述**：沙箱重启后文件同步显示成功但容器为空，因为 `.sync_manifest.json` 未绑定 `container_id`，新容器的文件被误判为已同步。

**影响**：沙箱重启后用户看到"同步成功"但实际容器内无文件。

**整改建议**：
- manifest 中记录 `container_id`
- 同步前校验 `container_id` 是否匹配
- 不匹配时自动重置 manifest 并执行全量同步

### 1.6 Token 统计缺失

**严重程度**：🟡 低

**问题描述**：`stream_chat` 端点在部分路径下未调用 `record_token_usage`，导致 SSE 流式对话的 token 消耗未被记录。

**影响**：TokenUsage 页面数据不完整。

**整改建议**：
- 在所有对话完成路径（包括 SSE 流结束）统一调用 `record_token_usage`
- 添加测试验证 token 记录的完整性

### 1.7 沙箱同步三层 Bug

**严重程度**：🟠 中

**问题描述**：
- `status` 命令盲信 manifest，不检查容器实际文件
- `push` 命令未验证容器连接状态
- UI 调用了错误的同步端点

**整改建议**：
- status 命令实际查询容器文件列表与 manifest 对比
- push 前验证容器可达性
- 修正 UI 调用路径

## 2. 设计层面的架构问题

### 2.1 全局锁成为并发瓶颈

**严重程度**：🔴 高

**问题描述**：`MultiAgentManager` 使用全局 `asyncio.Lock` 保护 `_workspaces` 和 `_agent_locks` 字典的变更。所有 Agent 的创建、加载、卸载操作都需要获取这个全局锁，在多 Agent 并发场景下会成为严重的性能瓶颈。

**影响**：
- 多 Agent 并发对话时可能互相阻塞
- 大量 Agent 启停操作时响应变慢
- 无法水平扩展

**整改建议**：
- **短期**：将全局锁拆分为 per-agent 锁 + 轻量级字典操作（使用 `dict.setdefault` 等原子操作）
- **中期**：引入 Agent 状态的外部存储（如 Redis），消除内存态与持久化态的一致性问题
- **长期**：支持多进程/多实例部署，使用分布式锁替代内存锁

### 2.2 请求驱动模型的局限

**严重程度**：🟡 中

**问题描述**：Agent 无常驻进程，每次调用在当次请求内执行图计算并返回。这意味着：
- 无法主动推送消息给用户
- 无法执行长时间后台任务（受 HTTP 超时限制）
- 无法实现真正的异步委派（当前只有同步 `task` 工具）

**影响**：
- 产品愿景中的异步委派、后台任务执行无法实现
- 长任务（如代码生成、数据分析）容易超时

**整改建议**：
- **短期**：利用 CronManager 的内部任务系统作为后台执行通道
- **中期**：引入消息队列（如 Redis Streams），实现真正的异步 Agent 执行
- **长期**：支持 Agent Protocol 的异步任务模式

### 2.3 图缓存失效粒度过粗

**严重程度**：🟡 中

**问题描述**：
- 安全配置变更会失效**所有** Agent 的图缓存，即使大部分 Agent 的中断规则没有变化
- SubAgent 列表变更也会触发所有主 Agent 的图重建

**影响**：频繁的全局失效导致大量 Agent 在下次对话时需要重新编译图，影响首响应时间。

**整改建议**：
- 安全配置变更时只失效受影响的 Agent（检查哪些 Agent 使用了被修改的工具中断规则）
- SubAgent 变更时只失效直接相关的主 Agent

### 2.4 SubAgent 字段不足

**严重程度**：🟠 中

**问题描述**：子 Agent 仅 3 个字段（name/description/system_prompt），无法为子代理独立配置：
- 工具集（无法实现"审计子代理只读"）
- 模型（无法实现"简单子任务用便宜模型"）
- 权限规则
- HITL 规则

**影响**：严重削弱多 Agent 协作的灵活性和成本控制能力。

**整改建议**：
- 在 `agent.json` 的 `subagents` 配置中扩展 `tools`、`model_id`、`permissions`、`interrupt_rules` 字段
- `SubAgentRegistry` 在构建时读取这些字段
- `AgentFactory` 在创建子 Agent 图时应用这些配置

### 2.5 SQLite Checkpointer 的并发限制

**严重程度**：🟠 中

**问题描述**：SQLite 不支持多实例共享写入，在 K8s 多实例部署时必须确保每个实例挂载独立的持久卷。但当前没有机制防止误配置。

**影响**：误配置会导致数据损坏。

**整改建议**：
- 启动时检测 Checkpointer 是否可写，给出明确警告
- 考虑生产环境推荐使用 PostgreSQL Checkpointer
- 在文档中明确标注 K8s 多实例部署的数据隔离要求

### 2.6 工作区布局迁移代码残留

**严重程度**：🟡 低

**问题描述**：`migrate_workspace_layout()` 函数用于从旧目录结构（`.agentcore/workspaces/`）迁移到新结构。虽然已完成迁移，但代码仍保留以兼容存量部署。

**整改建议**：
- 在下一个大版本中移除迁移代码
- 发布迁移指南，提醒存量部署升级

## 3. 安全相关问题

### 3.1 无认证/多租户支持

**严重程度**：🔴 高

**问题描述**：当前系统无认证机制，任何人访问端口即可使用所有功能。无法支持多用户、多角色场景。

**影响**：
- 无法在生产环境安全部署
- 无法实现 RBAC（基于角色的访问控制）
- 无法审计"谁做了什么"

**整改建议**：
- **Phase 1**：引入 API Key 认证（最简方案，适合内部使用）
- **Phase 2**：引入 JWT Token + 用户管理
- **Phase 3**：实现 RBAC（admin/operator/viewer 角色）

### 3.2 工作区逃逸风险

**严重程度**：🟠 中

**问题描述**：虽然有路径穿越防护，但 `execute` 工具允许执行任意 Shell 命令，理论上可以通过 `cd ../../` 等方式访问其他 Agent 的工作区。

**影响**：Agent 可能越权访问其他 Agent 的文件。

**整改建议**：
- `execute` 工具的 Shell 环境中设置 `HOME` 和 `PWD` 到 Agent 工作区
- 考虑使用 `chroot` 或容器隔离限制执行环境
- 在 `execute` 工具中添加路径校验

### 3.3 环境变量持久化的安全边界

**严重程度**：🟡 中

**问题描述**：`envs.json` 中存储的 API Key 以明文形式保存在磁盘。虽然 UI 展示时脱敏，但磁盘文件本身无加密。

**影响**：磁盘被非法访问时 API Key 可能泄露。

**整改建议**：
- 使用操作系统密钥链（如 Windows Credential Locker、macOS Keychain）存储敏感值
- 或使用 AES 加密存储，密钥从环境变量注入

### 3.4 审计日志可被清空

**严重程度**：🟡 中

**问题描述**：`approval_audit_log.json` 虽然设计为不可变追加，但没有文件完整性保护（如数字签名或哈希链）。拥有文件系统访问权限的人可以清空或篡改审计记录。

**整改建议**：
- 每条记录添加前一条的哈希值（哈希链）
- 定期将审计日志备份到只读存储
- 考虑使用数据库而非 JSON 文件存储审计日志

### 3.5 默认配置安全不足

**严重程度**：🟡 中

**问题描述**：
- `uvicorn` 默认绑定 `0.0.0.0:8000`，对所有网络接口开放
- 无 HTTPS 支持
- 无 CORS 限制（FastAPI 默认允许所有来源）

**影响**：局域网内的任何人都可以访问和操作 AgentCore。

**整改建议**：
- 默认绑定 `127.0.0.1`（仅本机），提供明确的配置文档说明如何开放
- 添加 CORS 配置选项
- 在文档中强调生产环境必须使用反向代理（Nginx）+ HTTPS

## 4. 性能与可扩展性问题

### 4.1 单 Worker 模式限制

**严重程度**：🟠 中

**问题描述**：当前推荐 `--workers 1` 启动，单进程处理所有请求。在高并发场景下：
- 单个慢请求（LLM 推理）会阻塞其他请求
- 全局锁在单进程内仍有争用
- 内存图缓存无法跨进程共享

**整改建议**：
- 短期：优化单进程内的协程并发（确保 LLM 调用不阻塞事件循环）
- 中期：支持多 Worker + 共享图缓存（Redis）
- 长期：微服务拆分（聊天服务、管理服务、沙箱服务独立部署）

### 4.2 Token 记录的内存压力

**严重程度**：🟡 低

**问题描述**：`token_usage.json` 最多存储 10000 条记录，每次追加需要读取整个文件、反序列化、追加、序列化、写回。在高频使用场景下可能造成性能问题。

**整改建议**：
- 使用 SQLite 替代 JSON 文件存储 token 使用记录
- 实现分页和自动归档
- 考虑使用时序数据库（如 InfluxDB）做成本分析

### 4.3 Checkpoint 数据库膨胀

**严重程度**：🟡 中

**问题描述**：`checkpoints.db` 存储所有会话的完整对话状态，长期使用后数据库可能膨胀到 GB 级别，影响性能和磁盘空间。

**整改建议**：
- 实现自动清理策略（如保留最近 N 天的 checkpoint）
- 提供手动清理工具
- 考虑将旧 checkpoint 归档到冷存储

### 4.4 前端首屏加载性能

**严重程度**：🟡 低

**问题描述**：Vite 构建的前端 bundle 包含 Ant Design 全量引入（虽有 tree-shaking，但实际效果有限），加上 24 个 i18n 模块同时加载，首屏加载时间可能较长。

**整改建议**：
- 实现路由级代码分割（React.lazy）
- i18n 模块按需加载
- 使用 CDN 加速静态资源

## 5. 前端 UI/UX 问题

### 5.1 未完成功能占位页面

**严重程度**：🟡 中

**问题描述**：以下 4 个页面仅显示"功能开发中，敬请期待"占位：
- **ACP**（Agent Communication Protocol）
- **Voice**（语音转写）
- **Channels**（频道管理）
- **Backups**（备份恢复）

**影响**：用户看到这些页面后会困惑为什么不可用。

**整改建议**：
- 方案 A：从导航菜单中移除未完成的页面
- 方案 B：保留但添加明确的"规划中"标签和预计上线时间
- 方案 C：实现最小可用版本（如 Backups 可以用简单的导出/导入实现）

### 5.2 沙箱后端选项不完整

**严重程度**：🟡 中

**问题描述**：Agent 配置页面的沙箱后端下拉框中，E2B 和 Daytona 选项显示 "coming soon" 且被禁用。当前仅支持 OpenSandbox。

**整改建议**：
- 实现 E2B 和 Daytona 后端适配器
- 或移除这些选项直到实际支持

### 5.3 侧边栏信息密度

**严重程度**：🟡 低

**问题描述**：侧边栏有 5 个分组、20+ 个菜单项，信息密度很高。新用户可能难以找到需要的功能。

**整改建议**：
- 实现智能菜单（根据使用频率排序）
- 添加搜索功能快速定位页面
- 支持用户自定义菜单布局

### 5.4 移动端适配

**严重程度**：🟡 低

**问题描述**：当前 Web UI 主要面向桌面端设计，移动端（手机/平板）体验不佳：
- 侧边栏在小屏幕上无法正常展开
- 聊天输入区域在键盘弹出后被遮挡
- 表格页面在窄屏上溢出

**整改建议**：
- 实现响应式布局（至少支持平板端）
- 聊天页面优先适配移动端
- 考虑开发 PWA 或原生 App

## 6. 第三方依赖风险

### 6.1 deepagents SDK 版本锁定

**严重程度**：🟠 中

**问题描述**：`deepagents>=0.7.0` 是核心依赖，但该项目仍在快速迭代中（2026 年 5 月才发布私有测试版）。版本更新可能带来：
- API 不兼容变更
- 中间件接口变化
- Checkpointer 行为变更

**影响**：SDK 升级可能导致 AgentCore 功能异常。

**整改建议**：
- 锁定具体版本（`deepagents==0.7.x`）
- 建立 SDK 升级测试流程
- 避免依赖 SDK 私有实现（已修复 `_ToolExclusionMiddleware` 问题）
- 建立 SDK 变更的监控和通知机制

### 6.2 OpenSandbox 响应率低

**严重程度**：🟡 低

**问题描述**：OpenSandbox 项目的 Issue 响应率仅 9%，首次响应中位数 23 小时。如果遇到集成问题，可能无法及时获得社区支持。

**整改建议**：
- 保持与 OpenSandbox API 的松耦合（通过 SandboxBackendProtocol 抽象）
- 记录所有与 OpenSandbox 的集成代码，方便后续替换
- 考虑自建轻量级沙箱服务作为备选

### 6.3 AIO Sandbox 的 seccomp 要求

**严重程度**：🟡 中

**问题描述**：AIO Sandbox 镜像需要 `--security-opt seccomp=unconfined` 才能正常运行，这在生产环境中可能被安全策略禁止。

**影响**：某些受控环境（如企业 K8s 集群）可能不允许 unconfined seccomp。

**整改建议**：
- 在文档中明确说明 seccomp 要求
- 提供最小权限的 seccomp profile（仅包含必要的系统调用）
- 考虑不依赖 Chromium/Playwright 的轻量级沙箱镜像

### 6.4 LangChain 生态的碎片化

**严重程度**：🟡 低

**问题描述**：项目依赖多个 LangChain 生态包（`langchain-openai`、`langgraph-checkpoint-sqlite`、`langchain-mcp-adapters`、`langchain-sandbox-opensandbox`），版本兼容性可能成为问题。

**整改建议**：
- 使用 `pip-compile` 或 `uv lock` 锁定所有依赖版本
- 定期运行兼容性测试
- 记录已知的版本兼容矩阵

## 7. 未完成功能的差距分析

### 7.1 产品愿景 vs 当前实现

| 产品愿景 | 当前状态 | 差距 |
|---------|---------|------|
| **多 Agent 协作（Aha Moment）** | 🟡 基础委派可用，但 SubAgent 仅 3 字段 | 缺少独立工具/模型/权限配置，协作灵活性不足 |
| **HITL 审批闭环** | 🟡 配置和 UI 就绪，但有 Bug（1.1-1.3） | 需修复审批死循环和按钮无响应问题 |
| **沙箱真执行** | 🟡 OpenSandbox/AIO 可用，但有同步 Bug | 需修复 manifest 绑定和同步三层问题 |
| **认证与多租户** | ⬜ 未实现 | 企业采用的硬性门槛 |
| **配置版本化与回滚** | 🟡 有手动备份机制，无自动版本管理 | 缺少版本历史、diff、一键回滚 |

| **频道管理** | ⬜ 仅页面占位 | 完全未实现 |
| **ACP 协议接入** | ⬜ 仅页面占位 | 完全未实现 |

### 7.2 描述智能生成

**当前状态**：子 Agent 的描述为 `Agent '{agent_id}' — {description} | Tools: ... | HITL: ...` 的模板化格式。

**差距**：LLM 无法精确判断何时委派给哪个子 Agent，委派命中率低。

**建议**：
- 为每个 Agent 提供结构化的能力标签（tags）
- 描述生成时包含能力标签、最近成功委派的案例
- 考虑使用 embedding 向量匹配委派目标

### 7.3 成本弹性

**当前状态**：所有 Agent 使用相同的模型配置。

**差距**：无法为子 Agent 分配更便宜的模型以降低成本。

**建议**：在 SubAgent 配置中支持独立的 `model_id` 字段。

### 8.1 现有文档过时

**严重程度**：🟠 中

**问题描述**：`/docs` 下的文档已过时：

- `AgentCore-架构诊断报告-SDK对齐版.md`：基于旧版本的诊断
- `deepagents-完全说明书.md`：基于旧版本 SDK
- `DefaultAgent通讯机制分析报告.md`：基于旧版委派机制
- `openspec/specs/` 和 `openspec/changes/` 目录为空

**整改建议**：
- 基于本文档（产品说明书 + 设计文档）更新所有现有文档
- 填充 openspec 的 specs 和 changes 目录
- 建立文档更新的 CI 检查

### 8.2 测试覆盖率不足

**严重程度**：🟠 中

**问题描述**：
- 20+ 个测试文件，但覆盖范围有限
- 缺少以下关键场景的测试：
  - 并发 Agent 对话的压力测试
  - 沙箱连接断开后的恢复测试
  - 大量 Agent（100+）的性能测试
  - 前端 E2E 测试（仅在 `.pytest_tmp/` 有截图脚本）

**整改建议**：
- 补充并发场景的单元测试和集成测试
- 添加沙箱故障恢复的测试用例
- 引入 Playwright 前端 E2E 测试框架
- 建立代码覆盖率目标（如 80%）

### 8.3 错误处理不一致

**严重程度**：🟡 中

**问题描述**：部分错误被 `except Exception` 静默吞掉（如 1.1 中的 Checkpointer 问题），导致问题在下游才暴露。

**整改建议**：
- 审查所有 `except Exception` 块，确保关键错误有日志记录
- 使用具体的异常类型而非 `except Exception`
- 建立错误分级：critical（阻断启动）/ warning（降级运行）/ info（正常行为）

### 8.4 缺少 API 版本化

**严重程度**：🟡 低

**问题描述**：当前所有 API 路径为 `/api/...`，没有版本号（如 `/api/v1/...`）。未来 API 不兼容变更时无法做渐进式迁移。

**整改建议**：
- 在下一个大版本中引入 `/api/v1/` 前缀
- 保留旧路径一段时间作为兼容层
