## 1. 系统架构总览

### 1.1 架构层次

AgentCore 采用**四层架构**：

```
┌─────────────────────────────────────────────────────┐
│                   前端 Console                       │
│  React 19 + TypeScript + Ant Design + Zustand       │
│  Vite 构建 → FastAPI 静态文件托管                     │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP / SSE
┌──────────────────────▼──────────────────────────────┐
│                  FastAPI 应用层                       │
│  路由分发 · 请求校验 · 中间件 · 生命周期管理            │
│  api.py → routers → services → repositories          │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│                  Agent 运行时层                       │
│  AgentFactory → deepagents SDK → LangGraph 图执行    │
│  Checkpointer · 中间件链 · 工具注入                   │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│                  基础设施层                           │
│  SQLite (状态) · APScheduler (调度) · Docker (沙箱)   │
│  磁盘文件系统 · OpenSandbox / AIO Sandbox            │
└─────────────────────────────────────────────────────┘
```

### 1.2 核心设计理念

| 理念 | 说明 |
|------|------|
| **请求驱动** | Agent 无常驻进程，每次调用在当次请求内执行图计算并返回 |
| **配置即状态** | Agent 的所有配置存储在 `agent.json`，是唯一事实来源 |
| **图缓存+失效** | 编译后的 LangGraph 图内存缓存，配置变更时自动失效重建 |
| **工作区隔离** | 每个 Agent 拥有独立的文件系统目录 |
| **可插拔后端** | 本地文件系统 / OpenSandbox / AIO Sandbox 可切换 |

### 2.2 请求处理流程

```
HTTP 请求
  → BasePathMiddleware（剥离子路径前缀）
  → FastAPI 路由分发
  → Router Handler（参数校验）
  → Service / Repository（业务逻辑）
  → AgentFactory（配置 → 图构建）
  → LangGraph 图执行（含中间件链）
  → Checkpointer（状态持久化）
  → HTTP 响应 / SSE 流
```

### 2.3 生命周期管理（Lifespan）

FastAPI 的 lifespan 在应用启动/关闭时执行：

**启动阶段**：
1. 初始化文件日志（`logs/backend.log`）
2. 确保数据目录存在 + 工作区布局迁移
3. 加载持久化环境变量（`envs.json` → `os.environ`）
4. 创建核心组件（ControlPlaneStore / AgentFactory / AgentRuntime / AgentService）
5. 清理孤儿工作区目录
6. 创建 ChatState（checkpointer + 图缓存）
7. 确保 Default Agent 存在（首次安装时播种）
8. 种子化全局技能池
9. 启动 CronManager（加载持久化任务 + 注册内部任务）
10. 启动记忆巩固调度
11. 启动审批过期清理调度

## 3. Agent 运行时设计

### 3.1 Agent 创建流程

```
用户创建 Agent（POST /api/agents）
  → 生成 agent_id
  → 创建工作区目录（.agentcore/workspace/agent/{agent_id}/）
  → 种子化内核文件（agent.md、bootstrap.md）
  → 持久化 agent.json（配置）
  → 注册到 ControlPlaneStore
  → 使所有 enable_subagents=true 的主 Agent 图失效
  → 返回 Agent 信息
```

### 3.2 Agent 图构建（AgentFactory）

AgentFactory 将 `agent.json` 配置映射为 deepagents SDK 调用：

```python
create_deep_agent(
    model=resolve_model(model_cfg),        # 从模型配置解析
    tools=tools,                           # 内置工具 + MCP 工具
    system_prompt=system_prompt,           # 内核文件组合
    backend=backend,                       # 本地/沙箱后端
    permissions=permissions,               # 文件权限规则
    interrupt_on=interrupt_on,             # HITL 中断规则
    memory=memory_paths,                   # 记忆文件路径
    skills=skills_dir,                     # 技能目录
    subagents=subagents,                   # 子 Agent 规格列表
    middleware=extra_middleware,            # 额外中间件
    enable_planning=enable_planning,       # 任务规划开关
)
```

### 3.3 图缓存机制

- **缓存键**：`agent_id`
- **缓存值**：编译后的 `CompiledStateGraph`
- **失效条件**：
  - 模型配置变更
  - 工具配置变更（启用/禁用）
  - 内核文件变更（agent.md 等）
  - MCP 服务器变更
  - 技能目录变更
  - 安全配置变更
  - Agent settings 变更
  - 子 Agent 白名单变更
- **失效范围**：单个 Agent 或所有 Agent（安全配置变更时）

### 3.4 内核文件系统

每个 Agent 的工作区包含以下内核文件：

| 文件 | 用途 | 可编辑 | 可删除 |
|------|------|--------|--------|
| `agent.md` | Agent 身份人设 | ✅ | ❌ |
| `bootstrap.md` | 首次引导 | ✅ | ✅（完成后） |
| `soul.md` | 核心人设（兼容） | ✅ | ❌ |
| `profile.md` | 用户偏好（兼容） | ✅ | ❌ |

**System Prompt 组合顺序**：`bootstrap.md` → `agent.md` → `profile.md` → `soul.md`

当 Agent 删除 `bootstrap.md` 时，系统自动触发图重建，后续对话以新的人设运行。

### 3.5 子 Agent 注册表（SubAgentRegistry）

```python
# 子 Agent 规格
@dataclass
class SubAgentSpec:
    agent_id: str
    description: str          # 动态生成：Agent 'xxx' — {description} | Tools: ...
    system_prompt: str        # 从 agent.md 提取
    # 以下字段当前未完全支持独立配置
    # tools: list[str]
    # model: str
    # permissions: dict
```

**动态发现机制**：
1. 新建 Agent 后，所有 `enable_subagents=true` 的主 Agent 图自动失效
2. 下次对话时重新构建图，SubAgent 列表重新聚合
3. LLM 通过 `task` 工具调用子 Agent

## 4. 聊天引擎设计

### 4.1 双端点架构

| 端点 | 协议 | 适用场景 |
|------|------|---------|
| `POST /api/chat` | REST 同步 | 简单对话、测试 |
| `POST /api/chat/stream` | SSE 流式 | 生产使用，实时体验 |

### 4.2 SSE 五路投影

流式端点通过 Server-Sent Events 推送五种通道：

| 通道 | 事件名 | 内容 |
|------|--------|------|
| LLM 输出 | `messages` | token 级文本、思考链、模型信息 |
| 子代理委派 | `subagents` | 委派开始/结束/结果 |
| 任务计划 | `todo` | write_todos 的任务清单变更 |
| HITL 中断 | `interrupts` | 中断事件、审批等待 |
| Token 消耗 | `token_usage` | 每轮的 input/output token |

**SSE 心跳保活**：25 秒间隔注入 `: keep-alive` 注释行，防止浏览器/代理断开长连接。

### 4.3 HITL 审批流程

```
Agent 调用危险工具
  → deepagents SDK 触发 interrupt()
  → ChatRouter 检测到 interrupt event
  → 暂停图执行，返回审批状态
  → 用户通过 POST /api/chat/approve 提交决策
  → 四种决策：approve / edit / reject / respond
  → 决策回写 Checkpointer
  → 图恢复执行
  → 审计日志记录
```

**审批清理**：每日 03:07 自动过期后台会话中超过 7 天未决的审批请求。

### 4.4 Checkpoint 持久化

- **存储后端**：SQLite（`langgraph-checkpoint-sqlite`）
- **线程隔离**：每个会话一个 `thread_id`
- **状态恢复**：对话恢复时从 Checkpointer 加载完整状态
- **Bootstrap 感知**：检测到 `bootstrap.md` 被删除后自动失效图缓存

### 4.5 会话归档

每轮对话结束后写入 `memory/sessions/YYYY-MM-DD.md`，供记忆巩固消费。

## 5. 沙箱子系统设计

### 5.1 抽象层设计

```
SandboxBackendFactory（ABC 接口）
  ├── OpenSandboxFactory   → OpenSandboxBackend
  └── AIOSandboxFactory    → AIOSandboxBackend
```

**SandboxBackendProtocol** 定义了统一接口：
- `execute(command)` — 执行 Shell 命令
- `read_file(path)` / `write_file(path, content)` — 文件操作
- `list_directory(path)` — 目录浏览
- `upload_file(file)` / `download_file(path)` — 文件传输
- `glob(pattern)` / `grep(pattern)` — 搜索

### 5.2 会话生命周期（SandboxSessionManager）

三种生命周期策略：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| **ephemeral** | Agent 停止时销毁沙箱 | 开发/测试 |
| **pause-on-idle** | 空闲超时后暂停，聊天时恢复 | 生产（成本敏感） |
| **persistent** | 持续运行直到 Agent 删除 | 长期运行任务 |

**关键机制**：
- 空闲检测器（后台循环）
- 容器死亡自动恢复
- 暂停感知（先查服务端状态再决定是否重建）
- 线程安全的会话管理

### 5.3 双向文件同步（SyncEngine）

基于 **SHA256 哈希**的增量同步：

```
Push: workspace → container
  → 计算本地文件 SHA256
  → 对比 .sync_manifest.json
  → 仅传输变更文件
  → 更新 manifest

Pull: container → workspace
  → 通过沙箱 API 获取容器文件列表
  → 对比 manifest
  → 仅拉取变更文件
  → 处理冲突（双方修改 → .remote-conflict 副本）

Status: 返回同步差异
  → 新增（仅本地）
  → 新增（仅远端）
  → 已修改（两端不同）
  → 已同步
```

**排除规则**：`agent.json`、隐藏文件、`__pycache__`、`node_modules`。

### 5.4 OpenSandbox 集成

```python
# 集成流程
from opensandbox import SandboxSync
from langchain_opensandbox import OpenSandboxBackend

sandbox = SandboxSync.create(
    image=image,
    timeout=timedelta(seconds=timeout),
    connection_config=conn_config,
    metadata={"agent_id": agent_id},
)
return OpenSandboxBackend(sandbox=sandbox, timeout=timeout)
```

### 5.5 AIO Sandbox 集成

```python
# AIO 镜像包含完整开发环境
AIO_DEFAULT_IMAGE = "ghcr.io/agent-infra/sandbox:latest"
AIO_ENTRYPOINT = ["/opt/gem/run.sh"]

    image=image,
    timeout=timedelta(seconds=timeout),
    connection_config=conn_config,
    entrypoint=list(AIO_ENTRYPOINT),

# 获取 AIO 服务器端点

    sandbox_id=sandbox.id,
    base_url=endpoint.endpoint,
    headers=headers,
    timeout=timeout,

```

## 6. 定时任务系统设计

### 6.1 调度器（CronManager）

- **底层**：APScheduler `AsyncIOScheduler`
- **持久化**：JSON 文件（`.agentcore/cron_jobs.json`）
- **保活**：60 秒间隔的 keepalive 循环（防止 WSL2 等平台事件循环休眠）

### 6.2 任务类型

| 类型 | 前缀 | 入用户列表 | 说明 |
|------|------|-----------|------|
| **用户任务** | 无 | ✅ | 用户通过 UI 创建的定时任务 |
| **内部任务** | `_internal:` | ❌ | 心跳、记忆巩固、审批清理 |

### 6.3 Cron 表达式处理

- 支持标准 5 段 cron 表达式
- 自动归一化：4 段/3 段自动补齐，数字星期转缩写
- 一次性执行：`run_at` 时间戳

### 6.4 执行历史

每个任务保留最近 50 条执行记录：
- `success` / `error` / `skipped` / `interrupted` / `cancelled`
- 记录执行时间、耗时、错误信息

## 7. 记忆系统设计

### 7.1 记忆层次

```
短期记忆（会话内）
  → LangGraph Checkpointer 保存每轮对话状态
  
会话归档（每日）
  → memory/sessions/YYYY-MM-DD.md

长期记忆（跨会话）
  → MEMORY.md（Agent 的事实和经验）
  → USER.md（关于用户的偏好）
```

### 7.2 记忆巩固管线

```
CronManager 触发（默认每天 03:00）
  → 读取 .consolidation_state.json（水印）
  → 扫描未处理的会话归档
  → 逐个归档喂给 Agent
  → Agent 自动分析提取长期事实
  → 合并到 MEMORY.md / USER.md
  → 更新水印
  → 超过 retain_days 的归档移入 archived/
```

**并发控制**：单并发限制，防止多次触发导致竞争。

## 8. 安全系统设计

### 8.1 权限模型

```
全局安全设置（security.json）
  ├── 启用/禁用开关
  ├── 需审批工具列表
  └── 允许的决策类型

Agent 级别 interrupt_rules
  └── 工具 → 策略映射（allow/deny/interrupt）

合并规则：Agent 级优先，全局作为兜底
```

### 8.2 审计日志

- **存储**：`approval_audit_log.json`（不可变追加，最多 10000 条）
- **原子写入**：保证崩溃安全
- **记录内容**：
  - agent_id, session_id, decision, tool_name
  - final_args, operator, timestamp

### 8.3 工作区隔离

- 每个 Agent 的文件操作限制在其 workspace 目录内
- 路径穿越防护：所有路径解析验证不超出 `workspace_dir`
- 内核文件保护：`agent.md` 等不可删除

### 8.4 环境变量安全

- API Key 存储在 `envs.json`，启动时加载到 `os.environ`
- UI 展示时脱敏为 `***`
- 支持环境变量引用模式（`api_key_env`）
- 不进代码库、不进日志明文

### 11.2 关键 API 详情

#### POST /api/chat/stream（SSE 流式聊天）

**请求体**：
```json
{
  "agent_id": "default",
  "message": "你好",
  "session_id": "可选，不传则新建"
}
```

**SSE 事件格式**：
```
event: messages
data: {"content": "你好", "type": "text", "model": "gpt-4o"}

event: token_usage
data: {"input_tokens": 100, "output_tokens": 50, "total_tokens": 150}

event: done
data: {"session_id": "xxx"}
```

#### POST /api/chat/approve（审批决策）

**请求体**：
```json
{
  "agent_id": "default",
  "session_id": "xxx",
  "decision": "approve|edit|reject|respond",
  "tool_name": "write_file",
  "args": { "修改后的参数" }
}
```

## 12. 第三方依赖

### 12.1 deepagents SDK

**角色**：Agent 运行时引擎（核心依赖）

**提供能力**：
- LangGraph 图编译与执行
- 中间件架构（TodoList / SubAgent / HITL / Summarization / Memory / Skills）
- 文件系统工具（ls / read_file / write_file / edit_file / delete / glob / grep / execute）
- 子 Agent 委派（task 工具）
- 权限控制（Allow / Deny / Interrupt）
- Checkpointer 集成

**版本要求**：`>=0.7.0`

### 12.2 OpenSandbox

**角色**：容器编排层（可选）

**提供能力**：
- Docker/K8s 容器生命周期管理
- 多语言 SDK（Python / Java / JS / C# / Go）
- 网络策略与凭证管理
- MCP 原生集成

**版本要求**：`>=0.3.0`

### 12.3 AIO Sandbox

**角色**：容器内执行环境（可选）

**提供能力**：
- 单容器集成：Shell + 浏览器 + VSCode + Jupyter
- MCP Hub 聚合
- 开发预览

**镜像**：`ghcr.io/agent-infra/sandbox:latest`

### 12.4 langchain-sandbox-opensandbox

**角色**：OpenSandbox → deepagents 桥接层

**提供**：`OpenSandboxBackend`，将 OpenSandbox SDK 封装为 deepagents 的 `SandboxBackendProtocol`。

## 13. 构建与部署

### 13.1 本地开发

```bash
# 后端
python -m uvicorn agentcore.api:app --host 127.0.0.1 --port 8000 --reload

# 前端（开发模式）
cd console && npm run dev
```

### 13.2 生产构建

```bash
# 前端构建
cd console && npm run build
# 构建产物自动复制到 src/agentcore/web/

# 后端打包
python -m build
```

### 13.3 Docker 部署

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install -e ".[sandbox]"
EXPOSE 8000
CMD ["uvicorn", "agentcore.api:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 13.4 子路径部署

通过 `AGENTCORE_BASE_PATH` 环境变量配置：
- 后端 `BasePathMiddleware` 自动剥离前缀
- 前端通过 `window.__AGENTCORE_BASE_PATH__` 运行时注入
- 支持 K8s 多实例按路径区分
