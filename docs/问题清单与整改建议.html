版本 1.0  ·  2026-08-31

🐛 已完成功能中的已知缺陷

1.1 HITL 审批：AsyncSqliteSaver 同步接口失效

🔴 高
生产环境 Checkpointer 使用 AsyncSqliteSaver，其同步 get_state() 方法不可用，异常被 except Exception 静默吞掉。导致 _get_all_interrupt_tools 静默返回空列表，fallback 只生成 1 个 decision，而 SDK 要求 decisions 数量等于 action_requests 数量。
影响：多工具同时触发审批时，审批全部失败并进入死循环。
整改：所有读取 interrupt 状态的辅助函数改为 async，使用 agent_graph.aget_state()；兼容 value 为 pydantic HITLRequest 对象；单元测试使用 AsyncMock。

1.2 SubAgent 委派列表白名单 Bug

🔴 高
_subagent_summaries 函数在构建子代理列表时未正确传递 subagent_ids 参数，导致委派列表显示不准确。
影响：主 Agent 可能委派给不可用的子 Agent，或遗漏可用的子 Agent。
整改：确保 SubAgentRegistry 在构建委派列表时完整传递所有子 Agent 的 ID 和描述；添加端到端测试验证。

1.3 审批按钮点击无响应

高
新会话中 currentSessionId 为 null，导致 submitApproval 静默退出，审批按钮点击无任何反馈。
影响：用户无法完成 HITL 审批流程。
整改：审批请求发送前校验 session_id 是否存在；缺失时给出明确错误提示。

1.4 SDK 模型对象 repr 泄漏到 UI

🟠 中
OpenSandbox SDK 返回的 pydantic 模型对象直接 str() 后会把整个 repr 渲染到前端，撑破表格列。
整改：归一化函数按语义优先级取字段：getattr(raw, 'state') → getattr(raw, 'value') → str(raw)。

1.5 沙箱同步 manifest 未绑定 container_id

🟠 中
沙箱重启后文件同步显示成功但容器为空，因为 .sync_manifest.json 未绑定 container_id。
整改：manifest 中记录 container_id；同步前校验是否匹配；不匹配时自动重置并全量同步。

1.7 沙箱同步三层 Bug

中
status 命令盲信 manifest；push 命令未验证容器连接状态；UI 调用了错误的同步端点。
整改：status 实际查询容器文件列表；push 前验证容器可达性；修正 UI 调用路径。

1.6 Token 统计缺失

🟡 低
stream_chat 端点在部分路径下未调用 record_token_usage，导致 SSE 流式对话的 token 消耗未被记录。
整改：在所有对话完成路径（包括 SSE 流结束）统一调用 record_token_usage。

️ 设计层面的架构问题

2.1 全局锁成为并发瓶颈

🔴 高
MultiAgentManager 使用全局 asyncio.Lock 保护 _workspaces 和 _agent_locks 字典。所有 Agent 的创建、加载、卸载操作都需要获取这个全局锁。
影响：多 Agent 并发对话时可能互相阻塞；大量 Agent 启停操作时响应变慢。
整改：短期拆分为 per-agent 锁 + 轻量级字典操作；中期引入外部存储（Redis）；长期支持多进程/多实例部署。

2.2 请求驱动模型的局限

🟡 中
Agent 无常驻进程，无法主动推送消息、无法执行长时间后台任务、无法实现真正的异步委派。
整改：短期利用 CronManager 内部任务系统；中期引入消息队列（Redis Streams）；长期支持 Agent Protocol 异步任务模式。

2.3 图缓存失效粒度过粗

🟡 中
安全配置变更失效所有 Agent 的图缓存；SubAgent 列表变更触发所有主 Agent 图重建。
整改：安全配置变更时只失效受影响的 Agent；SubAgent 变更时只失效直接相关的主 Agent。

2.4 SubAgent 字段不足

🟠 中
子 Agent 仅 3 个字段（name/description/system_prompt），无法独立配置工具集、模型、权限规则、HITL 规则。
整改：在 agent.json 的 subagents 配置中扩展 tools、model_id、permissions、interrupt_rules 字段。

2.5 SQLite Checkpointer 的并发限制

🟠 中
SQLite 不支持多实例共享写入，K8s 多实例部署时必须确保每个实例挂载独立的持久卷。
整改：启动时检测 Checkpointer 是否可写并给出警告；生产环境推荐 PostgreSQL Checkpointer。

🛡️ 安全相关问题

3.1 无认证/多租户支持

高
当前系统无认证机制，任何人访问端口即可使用所有功能。
整改：Phase 1 引入 API Key 认证 → Phase 2 JWT Token + 用户管理 → Phase 3 RBAC（admin/operator/viewer）。

3.2 工作区逃逸风险

🟠 中
execute 工具允许执行任意 Shell 命令，理论上可通过 cd ../../ 等方式访问其他 Agent 的工作区。
整改：execute 工具的 Shell 环境中设置 HOME 和 PWD 到 Agent 工作区；考虑使用 chroot 或容器隔离。

3.3 环境变量持久化的安全边界

🟡 中
envs.json 中存储的 API Key 以明文形式保存在磁盘，无加密保护。
整改：使用操作系统密钥链存储敏感值，或使用 AES 加密存储。

3.4 审计日志可被清空

中
approval_audit_log.json 没有文件完整性保护（如数字签名或哈希链）。
整改：每条记录添加前一条的哈希值（哈希链）；定期备份到只读存储。

3.5 默认配置安全不足

🟡 中
uvicorn 默认绑定 0.0.0.0:8000，无 HTTPS 支持，无 CORS 限制。
整改：默认绑定 127.0.0.1；添加 CORS 配置选项；文档强调生产环境必须使用反向代理 + HTTPS。

⚡ 性能与可扩展性问题

4.1 单 Worker 模式限制

中
当前推荐 --workers 1 启动，单个慢请求会阻塞其他请求，全局锁在单进程内仍有争用。
整改：短期优化协程并发；中期支持多 Worker + 共享图缓存（Redis）；长期微服务拆分。

4.2 Token 记录的内存压力

🟡 低
token_usage.json 最多 10000 条，每次追加需读取整个文件、反序列化、追加、序列化、写回。
整改：使用 SQLite 替代 JSON 文件；实现分页和自动归档。

4.3 Checkpoint 数据库膨胀

🟡 中
checkpoints.db 存储所有会话的完整对话状态，长期使用后可能膨胀到 GB 级别。
整改：实现自动清理策略；提供手动清理工具；考虑将旧 checkpoint 归档到冷存储。

4.4 前端首屏加载性能

低
Ant Design 全量引入 + 24 个 i18n 模块同时加载，首屏加载时间可能较长。
整改：实现路由级代码分割（React.lazy）；i18n 模块按需加载。

🎨 前端 UI/UX 问题

5.1 未完成功能占位页面

🟡 中
ACP、Voice、Channels、Backups 四个页面仅显示"功能开发中，敬请期待"。
整改：方案 A 从导航菜单移除；方案 B 保留但添加"规划中"标签；方案 C 实现最小可用版本。

5.2 沙箱后端选项不完整

中
Agent 配置页面的 E2B 和 Daytona 选项显示 "coming soon" 且被禁用。
整改：实现 E2B 和 Daytona 后端适配器，或移除这些选项直到实际支持。

5.3 侧边栏信息密度

🟡 低
侧边栏有 5 个分组、20+ 个菜单项，新用户难以找到需要的功能。
整改：实现智能菜单（按使用频率排序）；添加搜索功能；支持用户自定义菜单布局。

5.4 移动端适配

🟡 低
当前 Web UI 主要面向桌面端设计，移动端体验不佳。
整改：实现响应式布局（至少支持平板端）；聊天页面优先适配移动端。

📦 第三方依赖风险

6.1 deepagents SDK 版本锁定

🟠 中
deepagents>=0.7.0 是核心依赖，但该项目仍在快速迭代中。版本更新可能带来 API 不兼容变更。
整改：锁定具体版本；建立 SDK 升级测试流程；避免依赖 SDK 私有实现。

6.2 OpenSandbox 响应率低

🟡 低
OpenSandbox 项目的 Issue 响应率仅 9%，首次响应中位数 23 小时。
整改：保持与 OpenSandbox API 的松耦合；记录所有集成代码方便后续替换。

6.3 AIO Sandbox 的 seccomp 要求

中
AIO Sandbox 需要 --security-opt seccomp=unconfined，在某些受控环境可能被安全策略禁止。
整改：文档明确说明 seccomp 要求；提供最小权限的 seccomp profile。

6.4 LangChain 生态的碎片化

🟡 低
项目依赖多个 LangChain 生态包，版本兼容性可能成为问题。
整改：使用 uv lock 锁定所有依赖版本；定期运行兼容性测试。

📝 文档与工程规范问题

8.1 现有文档过时

🟠 中
/docs 下的文档已过时：product.md 标注的实现状态与实际不符；openspec/specs/ 和 openspec/changes/ 目录为空。
整改：基于新的产品说明书 + 设计文档更新所有现有文档；填充 openspec 目录。

8.2 测试覆盖率不足

🟠 中
缺少并发场景压力测试、沙箱故障恢复测试、大量 Agent 性能测试、前端 E2E 测试。
整改：补充并发单元测试和集成测试；引入 Playwright 前端 E2E 测试；建立代码覆盖率目标（80%）。

8.3 错误处理不一致

🟡 中
部分错误被 except Exception 静默吞掉，导致问题在下游才暴露。
整改：审查所有 except Exception 块；使用具体的异常类型；建立错误分级。

8.4 缺少 API 版本化

🟡 低
当前所有 API 路径为 /api/...，没有版本号。未来 API 不兼容变更时无法做渐进式迁移。
整改：在下一个大版本中引入 /api/v1/ 前缀；保留旧路径作为兼容层。
