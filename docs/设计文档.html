核心设计理念

理念说明
请求驱动Agent 无常驻进程，每次调用在当次请求内执行图计算并返回
配置即状态Agent 的所有配置存储在 agent.json，是唯一事实来源
图缓存+失效编译后的 LangGraph 图内存缓存，配置变更时自动失效重建
工作区隔离每个 Agent 拥有独立的文件系统目录
可插拔后端本地文件系统 / OpenSandbox / AIO Sandbox 可切换

生命周期管理（Lifespan）

启动阶段
1. 初始化文件日志（logs/backend.log）
2. 确保数据目录存在 + 工作区布局迁移
3. 加载持久化环境变量（envs.json → os.environ）
4. 创建核心组件（ControlPlaneStore / AgentFactory / AgentRuntime / AgentService）
5. 清理孤儿工作区目录
6. 创建 ChatState（checkpointer + 图缓存）
7. 确保 Default Agent 存在
8. 种子化全局技能池
9. 启动 CronManager（加载持久化任务 + 注册内部任务）
10. 启动记忆巩固调度
11. 启动审批过期清理调度

🤖 Agent 运行时

Agent 创建流程

POST /api/agents → 生成 agent_id → 创建工作区目录 → 种子化内核文件 → 持久化 agent.json → 注册到 ControlPlaneStore → 使所有 enable_subagents=true 的主 Agent 图失效 → 返回 Agent 信息

Agent 图构建（AgentFactory）

create_deep_agent(
    model=resolve_model(model_cfg),        # 从模型配置解析
    tools=tools,                           # 内置工具 + MCP 工具
    system_prompt=system_prompt,           # 内核文件组合
    backend=backend,                       # 本地/沙箱后端
    permissions=permissions,               # 文件权限规则
    interrupt_on=interrupt_on,             # HITL 中断规则
    memory=memory_paths,                   # 记忆文件路径
    skills=skills_dir,                     # 技能目录
    subagents=subagents,                   # 子 Agent 规格列表
    middleware=extra_middleware,            # 额外中间件
    enable_planning=enable_planning,       # 任务规划开关
)

图缓存失效条件

  • 模型配置变更
  • 工具配置变更（启用/禁用）
  • 内核文件变更（agent.md 等）
  • MCP 服务器变更
  • 技能目录变更
  • 安全配置变更（失效所有 Agent）
  • Agent settings 变更
  • 子 Agent 白名单变更

HITL 审批流程

Agent 调用危险工具 → deepagents SDK 触发 interrupt() → ChatRouter 检测到 interrupt event → 暂停图执行 → 用户通过 POST /api/chat/approve 提交决策（approve/edit/reject/respond）→ 决策回写 Checkpointer → 图恢复执行 → 审计日志记录

双向文件同步（SyncEngine）

基于 SHA256 哈希的增量同步：

  • Push：计算本地文件 SHA256 → 对比 .sync_manifest.json → 仅传输变更文件
  • Pull：获取容器文件列表 → 对比 manifest → 仅拉取变更文件
  • 冲突处理：双方修改时存储 .remote-conflict 副本，不静默覆盖
  • 排除规则：agent.json、隐藏文件、__pycache__、node_modules

⏰ 定时任务系统

  • 底层：APScheduler AsyncIOScheduler
  • 持久化：JSON 文件（.agentcore/cron_jobs.json）
  • 保活：60 秒间隔 keepalive 循环（防止 WSL2 事件循环休眠）

类型前缀入用户列表说明

memory/sessions/YYYY-MM-DD.md

记忆巩固管线

CronManager 触发（默认每天 03:00）→ 读取 .consolidation_state.json（水印）→ 扫描未处理的会话归档 → 逐个归档喂给 Agent → Agent 自动分析提取长期事实 → 合并到 MEMORY.md / USER.md → 更新水印 → 超过 retain_days 的归档移入 archived/

📦 第三方依赖

deepagents SDK

角色：Agent 运行时引擎（核心依赖）
能力：LangGraph 图编译与执行、中间件架构、文件系统工具、子 Agent 委派、权限控制、Checkpointer
版本：>=0.7.0

OpenSandbox（阿里巴巴）

角色：容器编排层（可选）
能力：Docker/K8s 容器生命周期管理、多语言 SDK、网络策略与凭证管理、MCP 原生集成
版本：>=0.3.0

AIO Sandbox

角色：容器内执行环境（可选）
能力：单容器集成 Shell + 浏览器 + VSCode + Jupyter + MCP Hub
镜像：ghcr.io/agent-infra/sandbox:latest

langchain-sandbox-opensandbox

角色：OpenSandbox → deepagents 桥接层
提供：OpenSandboxBackend，将 OpenSandbox SDK 封装为 deepagents 的 SandboxBackendProtocol

🔨 构建与部署

本地开发

# 后端
python -m uvicorn agentcore.api:app --host 127.0.0.1 --port 8000 --reload

# 前端（开发模式）
cd console && npm run dev

生产构建

# 前端构建
cd console && npm run build
# 构建产物自动复制到 src/agentcore/web/

# 后端打包
python -m build

子路径部署

通过 AGENTCORE_BASE_PATH 环境变量配置，后端 BasePathMiddleware 自动剥离前缀，前端通过 window.__AGENTCORE_BASE_PATH__ 运行时注入。
