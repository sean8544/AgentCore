## 1. 产品简介

AgentCore 是一个**多智能体管理平面**，用于创建、配置、编排和监控一群互相协作的 AI 智能体（Agent）。

**核心价值主张**：

> 让业务用户零代码组建一支"AI 员工团队"，让它们互相协作完成任务，并在权限、审批、成本监控的边界内被安全地管理。

**与单一对话机器人的区别**：AgentCore 不是另一个 ChatGPT 克隆，而是一个**管理平台**——你创建的不是"一个聊天窗口"，而是"一支有分工、可协作、可监管的 AI 团队"。

## 2. 系统要求与安装

### 2.1 环境要求

| 依赖 | 要求 |
|------|------|
| Python | 3.11+ |
| Node.js | 可选（仅构建前端 Web UI 需要） |
| Docker | 可选（沙箱功能需要） |
| 操作系统 | Windows / macOS / Linux |

### 2.2 安装方式

| 方式 | 适用场景 | 命令 |
|------|---------|------|
| Shell 一键安装 | Linux / macOS | `curl -fsSL <url>/install.sh \| bash` |
| PowerShell 安装 | Windows 推荐 | `irm <url>/install.ps1 \| iex` |
| CMD 安装 | Windows CMD | `scripts\install.bat` |
| Docker 部署 | 生产环境 | `docker compose up -d` |
| 源码安装 | 开发者 | `git clone` 后执行安装脚本 |

### 2.3 启动服务

```bash
# 安装后一键启动
agentcore-api

# 或手动启动
python -m uvicorn agentcore.api:app --host 0.0.0.0 --port 8000 --workers 1
```

启动后浏览器访问 **http://127.0.0.1:8000/** 即可使用 Web UI。

## 3. 快速上手（5 分钟教程）

### 第一步：首次进入——与默认助手打招呼

1. 打开浏览器访问 `http://127.0.0.1:8000/`
2. 系统自动创建了一个名为 `default` 的 Agent，点击左侧「聊天」进入对话
3. Agent 会显示**欢迎引导**，引导你完成：
   - 为 Agent 起名字、设定性格
   - 填写你的个人偏好（语言风格等）
   - 设置 Agent 的核心身份（`agent.md`）
4. 完成引导后，你拥有了一个个性化的 AI 助手

### 第二步：配置模型

1. 点击左侧「模型」进入模型管理页面
2. 点击「添加模型」，填写：
   - **端点 URL**（如 `https://api.openai.com/v1`）
   - **模型名称**（如 `gpt-4o`）
   - **API Key**
3. 点击「测试连接」确认可用后保存
4. 在 Agent 的「运行配置」页选择该模型

### 第三步：开始对话

1. 回到「聊天」页面
2. 在输入框输入问题，按 Enter 发送
3. Agent 会实时流式输出回复
4. 可在顶部切换不同模型进行对话

### 第四步（进阶）：创建多 Agent 团队

1. 点击左侧「智能体管理」
2. 点击「创建智能体」，填写 Agent 的身份、模型、能力
3. 创建多个专精 Agent（如"翻译专家"、"代码助手"）
4. 在「运行配置」中为某个 Agent 开启「委派能力」
5. 在聊天中，主 Agent 可以自动将子任务委派给专精 Agent

## 4. 功能模块详解

### 4.1 聊天（Chat）

**核心交互界面**，是日常使用最多的功能。

#### 基本操作

| 操作 | 说明 |
|------|------|
| **发送消息** | 在底部输入框输入，按 Enter 发送，Shift+Enter 换行 |
| **文件附件** | 点击附件按钮上传文件（≤20MB），Agent 可读取文件内容 |
| **停止生成** | 流式输出过程中可随时点击中断 |
| **切换模型** | 顶部下拉框可实时切换 LLM 模型 |
| **新建会话** | 点击会话列表顶部的"+"按钮 |

#### 会话管理

- **多会话**：同一 Agent 可拥有多个独立会话，每个会话保持独立的上下文记忆
- **会话列表**：左侧显示所有会话，可切换、重命名、删除
- **会话恢复**：历史会话可随时恢复继续

#### 高级功能

| 功能 | 说明 |
|------|------|
| **思考链展示** | 显示 Agent 的推理过程（可折叠），实时带脉冲动画 |
| **工具调用卡片** | 显示 Agent 调用了哪些工具、参数是什么、返回什么结果 |
| **任务计划面板** | Agent 使用 `write_todos` 创建结构化任务清单，带进度条和状态标记 |
| **子代理委派气泡** | 显示 Agent 将任务委派给了哪个子 Agent，可点击跳转 |
| **委派记录时间线** | 垂直时间线展示完整委派历史 |
| **Token 消耗** | 每条消息显示 input/output token 数量 |
| **Markdown 渲染** | 支持 GFM 表格、代码高亮、文件链接（点击跳转文件页） |
| **快捷指令** | 输入 `/approve` 或 `/deny` 快速审批 |

#### HITL 审批卡片

当 Agent 执行危险操作（如删除文件）被拦截时，聊天界面会弹出**审批卡片**：

- 显示操作详情（工具名、参数、原因）
- 提供三种操作：
  - **批准**：允许执行
  - **编辑后批准**：修改参数后执行
  - **拒绝**：阻止操作
- 决策后 Agent 按结果继续执行
- 所有决策被记录到审计日志

### 4.3 智能体管理（Agents）

#### 查看所有 Agent

| 字段 | 说明 |
|------|------|
| ID | Agent 唯一标识 |
| 状态 | idle / busy / unloaded |
| 会话数 | 该 Agent 拥有的会话总数 |
| 创建时间 | 创建日期 |

#### 创建 Agent

**三步创建向导**：

1. **基础信息**
   - Agent ID（唯一标识，如 `translator`）
   - 描述（一句话说明 Agent 的职责）
   - 系统提示词（定义 Agent 的人格和行为规则）

2. **模型配置**
   - 选择模型来源：继承默认 / 选择已有模型 / 自定义
   - 可为不同 Agent 分配不同模型（控制成本）

3. **能力与协作**
   - **委派能力**：是否允许该 Agent 调用其他 Agent 完成子任务
   - **任务拆解**：是否启用 `write_todos` 工具进行任务规划
   - **HITL 审批**：配置哪些操作需要人工审批
   - **执行环境**：本地文件系统 / 沙箱隔离容器

#### 管理 Agent

| 操作 | 说明 |
|------|------|
| **启动（Start）** | 预热加载，加快首次响应速度 |
| **停止（Stop）** | 释放内存，保留磁盘文件，下次使用自动重建 |
| **重载（Reload）** | 热重载工作区，配置变更后重新生效 |
| **删除（Delete）** | 永久删除 Agent 及其所有工作区文件、会话、配置 |

> **注意**：删除操作不可逆，请谨慎操作。

### 4.4 会话管理（Sessions）

查看和管理所有 Agent 的历史会话：

- **会话列表**：显示会话 ID、消息数、创建/更新时间
- **会话详情**：点击展开查看完整对话记录
- **步骤时间线**：回溯 Agent 每一步执行，含 token 消耗
- **按 Agent 筛选**：过滤查看特定 Agent 的会话
- **批量删除**：一次清理多个会话
- **待审批过滤**：只查看有未审批操作的会话

### 4.5 文件管理（Files）

管理 Agent 的**虚拟文件系统**——每个 Agent 拥有独立的工作区目录。

#### 文件浏览

- **内核文件**（红色高亮）：`agent.md`（身份人设）、`bootstrap.md`（首次引导，完成后自动删除）
- **工作区文件**：Agent 在对话中创建的所有文件
- **技能目录**（`skills/`）：Agent 加载的技能文件

#### 文件操作

| 操作 | 说明 |
|------|------|
| **在线编辑** | 点击文件可在线编辑内容，保存后 Agent 下次对话生效 |
| **文件上传** | 支持上传任意文件到工作区 |
| **文件下载** | 下载文件到本地 |
| **删除** | 删除文件或目录（内核文件不可删除） |

#### 沙箱同步

如果 Agent 配置了沙箱环境，文件管理页还提供：
- **推送到沙箱**：将本地工作区文件推送到沙箱容器
- **从沙箱拉回**：将沙箱中的修改同步回本地
- **双向同步**：智能合并两端的变更
- **同步状态标记**：已同步 / 待推送 / 待拉回 / 冲突

### 4.6 记忆管理（Memory）

Agent 的**长期记忆系统**，让 Agent 跨会话记住重要信息。

#### 记忆文件

| 文件 | 用途 |
|------|------|
| `MEMORY.md` | Agent 的长期记忆（事实、经验、教训） |
| `USER.md` | 关于用户的偏好和背景信息 |

#### 记忆巩固（Sleep-time Compute）

系统自动在后台执行**记忆巩固**：
1. 读取最近的会话归档（`memory/sessions/YYYY-MM-DD.md`）
2. Agent 自动分析提取长期有用的事实
3. 将提取的事实合并到 `MEMORY.md` 或 `USER.md`
4. 过期的归档自动移入 `archived/` 目录

#### 配置选项

| 配置 | 说明 |
|------|------|
| 巩固计划（cron） | 默认每天凌晨 3 点执行 |
| 保留天数 | 归档文件保留时长（1-3650 天） |
| 记忆上限 | MEMORY.md 最大大小（1-1024 KB） |
| 超时设置 | 单次巩固的最大时间 |

## 5. 多 Agent 协作

### 5.1 协作模型

AgentCore 采用**主从协作模型**：

```
用户 → 主 Agent（开启委派能力）→ 通过 task 工具委派给子 Agent
                                  ↓
                          子 Agent 独立执行
                                  ↓
                          只回传最终结果给主 Agent
                                  ↓
                          主 Agent 整合后回复用户
```

**关键特性**：
- **上下文隔离**：子 Agent 的中间过程不进入主 Agent 的上下文
- **动态发现**：新建 Agent 后，所有开启委派的主 Agent 自动发现
- **角色切换**：同一个 Agent 可以既是主（调用别人）又是从（被别人调用）

### 5.2 协作流程示例

1. 用户在 Chat 选择开启了委派的 Agent A
2. 用户说："帮我把这段英文翻译成中文，然后写成周报"
3. Agent A 判断需要两个子任务：翻译 + 撰写
4. Agent A 通过 `task` 工具委派翻译任务给「翻译专家」Agent
5. 翻译专家独立完成翻译，回传结果
6. Agent A 再委派撰写任务给「文案专家」Agent
7. 文案专家独立完成撰写，回传结果
8. Agent A 整合两个结果，回复用户

## 6. Agent 生命周期

### 状态说明

| 状态 | 含义 |
|------|------|
| **idle** | 无在途请求，正常静息状态 |
| **busy** | 正在处理请求 |
| **unloaded** | 已卸载内存态（stop 操作后），磁盘文件保留 |

### 生命周期操作

| 操作 | 行为 | 可恢复性 |
|------|------|---------|
| **启动（Start）** | 预热加载 workspace 到内存 | - |
| **停止（Stop）** | 释放内存态，磁盘文件保留 | 下次使用自动重建 |
| **重载（Reload）** | 热重载 workspace，重建 Agent 图 | - |
| **删除（Delete）** | 删除所有数据（工作区、会话、配置等） | **不可逆** |

### 首次对话引导

新建 Agent 会自动播种 `bootstrap.md` 引导文件，引导完成身份设置。Agent 完成设置后会删除该文件，此后永远不会再创建。

## 9. 常见问题

### Q: Agent 不回复怎么办？
A: 检查模型配置是否正确、API Key 是否有效。在「模型」页面使用「测试连接」功能验证。

### Q: 多 Agent 委派不生效？
A: 确保主 Agent 已开启「委派能力」，且目标子 Agent 已创建。

### Q: 沙箱文件同步冲突？
A: 当本地和沙箱同时修改同一文件时会产生冲突。系统会保存 `.remote-conflict` 副本，请手动合并。

### Q: 审批卡片不出现？
A: 检查「安全」页面是否启用了全局审批策略，以及 Agent 的 HITL 规则是否配置了对应工具。
