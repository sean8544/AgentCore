# 技能创建技能

本技能指导你为用户创建高质量的 Agent 技能。

## 技能是什么

每个技能是一个目录，包含一个 `SKILL.md`（可附参考文档与脚本）：

```
skill-name/
├── SKILL.md        # 必需 — 主指令（YAML frontmatter + Markdown 正文）
├── reference.md    # 可选 — 详细参考
├── examples.md     # 可选 — 用法示例
└── scripts/        # 可选 — 工具脚本
```

存放位置（以你的视角）：

- **你自己的技能**：工作区相对路径 `skills/<skill-name>/SKILL.md`。你的文件工具以工作区为根目录，创建技能一律写这个相对路径。
- 全局技能池由系统在服务器端管理，你**看不到也访问不到**它的路径；管理员从池安装时会复制一份进你的 `skills/` 目录。

## 创建前：先收集需求

1. **目的与范围** — 这个技能要帮用户完成什么任务？
2. **触发场景** — 什么时候应该自动应用它？
3. **领域知识** — agent 需要哪些它本来不知道的专门信息？
4. **输出偏好** — 有没有指定的模板、格式或风格？
5. **现有惯例** — 有没有可参考的例子？

信息不足时主动向用户提问，不要臆测。若对话中已讨论过相关工作流，可直接从中提炼。

## SKILL.md 格式

```markdown
---
name: skill-name          # 小写字母/数字/连字符，≤64 字符，与目录同名
description: 一句话说明做什么 + 什么时候用
---

# 标题

## 何时使用
## 执行步骤 / 核心工作流
## 注意事项
```

## Description 是命脉

agent 靠 description 决定是否应用该技能：

- 第三人称、面向任务：「浏览器自动化技能：当用户需要打开网页、填写表单…」
- 同时包含 **WHAT**（做什么）与 **WHEN**（何时用、触发关键词）
- 避免「帮助处理文档」这类空泛表述

## 写作四原则

1. **精炼至上** — agent 已经很聪明，只写它不知道的；每段都问「值这些 token 吗」
2. **正文 <500 行** — 细节拆到 reference.md / examples.md，SKILL.md 里一层链接引用（嵌套过深的引用可能只被部分读取）
3. **匹配自由度** — 灵活任务给文字指引；有固定套路给模板；脆弱操作（迁移、校验）给可执行脚本
4. **术语一致** — 一个概念一个词，全文统一（不要 URL/route/path 混用）

## 常用模式

- **模板模式** — 直接给出输出格式模板
- **示例模式** — input → output 成对示例
- **工作流模式** — 复杂操作拆成 checklist 步骤，逐打勾推进
- **条件分支** — 「新建内容？→ 走 A；编辑已有？→ 走 B」
- **反馈回路** — 产出后立即跑校验脚本，失败则修再验，通过才继续

## 反面模式

- 一堆并列选项不给默认 → 应为「默认方案 + 逃生舱」
- 时效性表述（「某月之前用旧 API」）→ 应收进「已废弃」折叠区
- 空泛命名（helper、utils）→ 用 processing-pdfs 这类具体名
- 冗长背景铺垫（「PDF 是一种常见文件格式…」）

## 完成前自检

- [ ] name 与目录同名且符合命名规则
- [ ] description 具体、含触发词、第三人称
- [ ] 正文 <500 行、术语一致、示例具体不抽象
- [ ] 文件引用只有一层深
- [ ] 无时效性内容

## 落地方式（agent 视角）

1. 用你自己的文件工具创建 `skills/<新技能名>/SKILL.md`（相对路径，不要写任何服务器绝对路径）。
2. 写完后回读确认 frontmatter 与正文完整。
3. **生效时机**：技能列表在会话开始时扫描一次，当前对话不会热加载新技能；新开会话即可使用。可提醒用户在新会话里验证。
4. **沙箱注意**：若你绑定了解执行沙箱，文件写在沙箱容器内，可能不持久化回工作区；创建后建议请用户在「文件」页面确认 `skills/<名>/SKILL.md` 已落盘。
5. **分享给其他 agent**：如需入库复用，请用户在技能池页面把这份 SKILL.md 内容新建为池技能，再安装给其他 agent（池→agent 的安装/同步由用户在 UI 操作）。
